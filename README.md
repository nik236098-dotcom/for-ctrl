# goskey-forwarder

Автоматическая пересылка новых договоров из приложения **Госключ** в Telegram —
для одного или двух аккаунтов (например, личный + ИП, так как сам Госключ
не поддерживает переключение между аккаунтами в одном приложении).

Так как Госключ недоступен на iOS, приложение крутится в headless-контейнере
Android (redroid) на вашем VDS, а Python-скрипт периодически проверяет список
документов и присылает новые PDF в Telegram-бота.

## Архитектура

Каждый аккаунт Госключ — отдельный Android-контейнер (свой ADB-порт, своя
сессия) и отдельный процесс Python-скрипта. Они полностью независимы: слёт
сессии или сбой в одном не трогает второй.

```
VDS (Ubuntu, KVM)
 ├─ Docker
 │   ├─ redroid-personal (Android, порт ADB 5555) → Госключ, личный аккаунт
 │   └─ redroid-ip       (Android, порт ADB 5565) → Госключ, аккаунт ИП
 └─ Python (systemd, по процессу на аккаунт)
      ├─ goskey-forwarder@personal (.env.personal) → ADB 127.0.0.1:5555
      └─ goskey-forwarder@ip       (.env.ip)       → ADB 127.0.0.1:5565
           каждый: раз в POLL_INTERVAL_SECONDS проверяет документы →
           новый → adb pull → шлёт PDF в Telegram с пометкой [Личный]/[ИП]
```

Нужен только один аккаунт? Просто не поднимайте второй контейнер/сервис —
всё остальное работает точно так же.

## Установка по шагам

### 1. Проверка сервера

```bash
bash scripts/check_prereqs.sh
```

Скажет: тип виртуализации, RAM/CPU (хватит ли на один аккаунт или на оба
сразу), Docker, свободны ли порты 5555/5565, поддержка binder-модуля
(без него redroid не запустится).

### 2. Установка зависимостей и запуск redroid

```bash
bash setup.sh
cp .env.example .env        # порты ADB для docker-compose, обычно менять не нужно
docker compose up -d        # поднимет ОБА контейнера
```

Нужен только один аккаунт:
```bash
docker compose up -d redroid-personal
```

Проверить, что ADB видит устройства:
```bash
adb connect 127.0.0.1:5555   # личный
adb connect 127.0.0.1:5565   # ИП
adb devices
```

### 3. Установка Госключ в каждый контейнер

APK один и тот же файл, ставится в оба контейнера отдельно:

```bash
adb -s 127.0.0.1:5555 install goskey.apk
adb -s 127.0.0.1:5565 install goskey.apk
```

(Про источник APK — у коллег, которые уже гоняют его в эмуляторах, либо
через RuStore; сверьте контрольную сумму/издателя, раз приложение хранит
ключ подписи.)

### 4. Первый вход в каждый аккаунт

Серверу нечем показать вам экран — подключаемся временно через `weditor`
(показывает скриншот в браузере и позволяет кликать/вводить текст прямо
по нему, отдельный `scrcpy` не обязателен):

```bash
pip install weditor
weditor   # http://localhost:17310 — подключаетесь к 127.0.0.1:5555 или :5565
```

Заходите в Госключ вручную (телефон/логин, пароль, код 2FA) — по разу для
каждого контейнера, под соответствующий аккаунт. Дальше контейнеры должны
оставаться запущенными — повторный логин обычно не потребуется.

### 5. Определение UI-элементов приложения

Тот же `weditor` — кликаете по элементам списка документов, экрану логина
и экрану ввода кода, смотрите `resourceId`/`text` в правой панели.
Найденные значения впишите в `bot/goskey_automation.py` вместо `# TODO`
(общий файл для обоих аккаунтов — экраны Госключ одинаковые что для
личного, что для ИП, отличается только содержимое).

### 6. Настройка Telegram-бота

1. Через [@BotFather](https://t.me/BotFather) создайте бота (можно один
   бот на оба аккаунта — сообщения помечаются `[Личный]`/`[ИП]`).
2. Напишите боту любое сообщение, откройте
   `https://api.telegram.org/bot<TOKEN>/getUpdates` — найдите `chat.id`.
3. Скопируйте `.env.personal.example` → `.env.personal` и
   `.env.ip.example` → `.env.ip`, заполните оба (токен/chat_id можно
   одинаковые, ADB_DEVICE — разный, см. комментарии в файлах).

### 7. Запуск

Тест вручную (по одному аккаунту за раз, в разных терминалах):
```bash
python -m venv venv
./venv/bin/pip install -r requirements.txt
./venv/bin/python -m bot.poller --env .env.personal
./venv/bin/python -m bot.poller --env .env.ip
```

Постоянная работа — через systemd (шаблонный юнит, `%i` — имя аккаунта):

```bash
sudo cp goskey-forwarder@.service /etc/systemd/system/
sudo sed -i "s#/opt/goskey-forwarder#$(pwd)#" /etc/systemd/system/goskey-forwarder@.service
sudo systemctl daemon-reload

sudo systemctl enable --now goskey-forwarder@personal
sudo systemctl enable --now goskey-forwarder@ip

sudo journalctl -u goskey-forwarder@personal -f   # логи личного аккаунта
sudo journalctl -u goskey-forwarder@ip -f         # логи ИП
```

## Если на сервере уже есть другой проект

Спокойно ставится рядом с другими ботами/скриптами (например, headless-Chrome
проектом на курсы валют) — контейнеры и Python-окружение (`venv`) изолированы
друг от друга, Telegram-боты не пересекаются (у каждого свой токен).
`bash scripts/check_prereqs.sh` проверяет, свободны ли порты 5555 и 5565.
Если заняты — смените `ADB_HOST_PORT_PERSONAL`/`ADB_HOST_PORT_IP` в `.env`
и соответствующий `ADB_DEVICE` в `.env.personal`/`.env.ip`.

## Что если сессия Госключ слетит

Полностью автоматический вход невозможен принципиально — Госключ защищён
двухфакторной аутентификацией именно для того, чтобы вход нельзя было
пройти без живого человека (это касается любого сервиса с 2FA, не только
Госключа). Сделаны три смягчения — независимо для каждого аккаунта:

1. **Бот сам заметит и напишет.** Каждый цикл опроса проверяет, не
   вылетели ли мы на экран логина — если да, в Telegram прилетит
   предупреждение с пометкой `[Личный]`/`[ИП]` (не чаще раза в
   `LOGIN_ALERT_COOLDOWN_HOURS` часов), а как только сессия
   восстановится — придёт подтверждение.

2. **Полуавтоматическое восстановление.** Если задать `GOSKEY_LOGIN` и
   `GOSKEY_PASSWORD` в `.env.personal`/`.env.ip`, бот сам пройдёт экран
   логин+пароль, а когда дойдёт до кода из SMS — просто напишет вам в
   Telegram и подождёт ответа (до `OTP_WAIT_TIMEOUT_SECONDS`, по
   умолчанию 10 минут). Отвечаете цифрами из SMS прямо в чат с ботом —
   вход завершён без weditor/scrcpy. Двухфакторка не обходится, её
   по-прежнему проходите вы сами, просто через Telegram.

3. **Ежедневный бэкап данных контейнеров** (обоих сразу) — восстановление
   после сбоя занимает пару команд, а не повторный вход с нуля:

```bash
# добавить в crontab (crontab -e)
0 4 * * * cd /path/to/for-ctrl && bash scripts/backup_redroid.sh >> backups/backup.log 2>&1
```

Если ничего из этого не спасло (например, у самого Госключа истёк
токен) — тогда только руками через weditor, как при первой установке
(п.4). Но при живых контейнерах это должно происходить редко.

## VPN с российским IP для телефона

В папке [`vpn/`](vpn/README.md) — отдельный, независимый от Госключа проект:
сервер WireGuard на этом же VDS + Android-приложение (собирается в APK),
которое даёт телефону российский внешний IP. Полезно, если с зарубежного
адреса не пускают Госуслуги, банки и RuStore. Установка и сборка APK —
в [vpn/README.md](vpn/README.md).

## Важно

- Пароль от Госключ (если решите его хранить) лежит только в
  `.env.personal`/`.env.ip` на вашем сервере — оба файла в `.gitignore`,
  в git не попадают.
- Если контейнер redroid пересоздать с удалением volume
  (`docker compose down -v`) — сессия этого аккаунта сотрётся, второй
  аккаунт не затронется.
