# goskey-forwarder

Автоматическая пересылка новых договоров из приложения **Госключ** в Telegram.

Так как Госключ недоступен на iOS, приложение крутится в headless-контейнере
Android (redroid) на вашем VDS, а Python-скрипт периодически проверяет список
документов и присылает новые PDF в Telegram-бота.

## Архитектура

```
VDS (Ubuntu, KVM)
 ├─ Docker
 │   └─ redroid-контейнер (Android без экрана)
 │        └─ Госключ (ставится через adb install, APK сами скачиваете)
 └─ Python-скрипт (systemd-сервис, работает постоянно)
      ├─ uiautomator2 → подключается к redroid по ADB (127.0.0.1:5555)
      ├─ раз в POLL_INTERVAL_SECONDS проверяет список документов
      ├─ новый документ → adb pull скачивает PDF
      └─ шлёт PDF в Telegram через Bot API
```

## Установка по шагам

### 1. Проверка сервера

```bash
bash scripts/check_prereqs.sh
```

Скрипт скажет: тип виртуализации, есть ли Docker, сколько RAM/CPU, есть ли
поддержка binder-модуля (без него redroid не запустится). Если binder не
найден — увидите инструкцию в выводе скрипта, что доустановить.

### 2. Установка зависимостей и запуск redroid

```bash
bash setup.sh
docker compose up -d
```

Через 20-30 секунд после старта в контейнере поднимется Android и adbd на
порту 5555.

Проверить, что ADB видит устройство:
```bash
adb connect 127.0.0.1:5555
adb devices
```

### 3. Установка Госключ

Скачайте APK Госключ (у коллег, которые уже гоняют его в эмуляторах, либо
через RuStore/официальный источник — см. обсуждение в README о проверке
контрольной суммы) и положите рядом со скриптами, затем:

```bash
adb -s 127.0.0.1:5555 install goskey.apk
```

### 4. Первый вход в приложение

Серверу нечем показать вам экран — подключаемся временно через `scrcpy`
с вашего ноутбука через SSH-туннель:

```bash
# на ноутбуке
ssh -L 5555:127.0.0.1:5555 user@ваш-vds-ip
# в отдельном окне терминала, тоже на ноутбуке
scrcpy -s 127.0.0.1:5555
```

Откроется зеркало экрана Android — заходите в Госключ вручную (телефон,
пароль, код 2FA) один раз. Дальше контейнер должен оставаться запущенным —
повторный логин обычно не потребуется, скрипт открывает уже
авторизованное приложение.

### 5. Определение UI-элементов приложения

Это единственный шаг, который нельзя сделать заранее без доступа к реальному
приложению — нужно посмотреть, как называются элементы списка документов и
кнопки. Пока приложение открыто в scrcpy, снимите дамп экрана:

```bash
python -m uiautomator2 dump  # или через weditor (см. ниже)
```

Либо поднимите `weditor` — веб-инструмент для просмотра дерева элементов:

```bash
pip install weditor
weditor  # откроется на http://localhost:17310, кликаете по элементам списка документов
```

Найденные `resourceId`/`text` элементов списка документов и кнопки открытия
документа впишите в `bot/goskey_automation.py` — там помечено `# TODO`.
Без этого шага бот не будет знать, где искать документы (я не могу
угадать внутренние ID чужого приложения без доступа к нему).

### 6. Настройка Telegram-бота

1. Через [@BotFather](https://t.me/BotFather) создайте бота, получите токен.
2. Напишите боту любое сообщение, затем откройте
   `https://api.telegram.org/bot<TOKEN>/getUpdates` — найдите свой `chat.id`.
3. Скопируйте `.env.example` в `.env` и заполните.

### 7. Запуск

Тест вручную:
```bash
pip install -r requirements.txt
python -m bot.poller
```

Постоянная работа — через systemd:

```bash
python -m venv venv
./venv/bin/pip install -r requirements.txt

sudo cp goskey-forwarder.service /etc/systemd/system/
sudo sed -i "s#/opt/goskey-forwarder#$(pwd)#" /etc/systemd/system/goskey-forwarder.service
sudo systemctl daemon-reload
sudo systemctl enable --now goskey-forwarder
sudo journalctl -u goskey-forwarder -f   # логи
```

## Если на сервере уже есть другой проект

Спокойно ставится рядом с другими ботами/скриптами (например, headless-Chrome
проектом на курсы валют) — контейнеры и Python-окружение (`venv`) изолированы
друг от друга, Telegram-боты не пересекаются (у каждого свой токен). Единственное,
что стоит проверить заранее — `bash scripts/check_prereqs.sh` теперь также
смотрит, свободен ли порт 5555 (ADB). Если занят — задайте `ADB_HOST_PORT` в
`.env` на свободный порт, `ADB_DEVICE` должен указывать на тот же порт.

## Что если сессия Госключ слетит

Полностью автоматический вход невозможен принципиально — Госключ защищён
двухфакторной аутентификацией именно для того, чтобы вход нельзя было
пройти без живого человека (это касается любого сервиса с 2FA, не только
Госключа). Поэтому вместо попытки обойти это сделаны два смягчения:

1. **Бот сам заметит и напишет.** Каждый цикл опроса проверяет, не
   вылетели ли мы на экран логина — если да, в Telegram сразу прилетит
   предупреждение (не чаще раза в `LOGIN_ALERT_COOLDOWN_HOURS` часов,
   по умолчанию 6), а как только сессия восстановится — придёт
   подтверждение. Не будет ситуации "молчал месяц, а оказывается всё
   сломалось в первый день".

2. **Ежедневный бэкап данных контейнера** — восстановление после сбоя
   занимает пару команд, а не полную переустановку и повторный вход:

```bash
# добавить в crontab (crontab -e)
0 4 * * * cd /path/to/for-ctrl && bash scripts/backup_redroid.sh >> backups/backup.log 2>&1
```

Если сессия всё же слетела и бэкап не спасает (например, у самого
Госключа истёк токен) — тогда только руками через scrcpy, как при первой
установке (README, п.4). Но при живом контейнере это должно происходить
редко.

**Полуавтоматическое восстановление.** Если задать `GOSKEY_LOGIN` и
`GOSKEY_PASSWORD` в `.env`, бот сам пройдёт экран логин+пароль, а когда
дойдёт до кода из SMS — просто напишет вам в Telegram и подождёт ответа
(до `OTP_WAIT_TIMEOUT_SECONDS`, по умолчанию 10 минут). Вы отвечаете
цифрами из SMS прямо в чат с ботом — и всё, вход завершён без scrcpy.
Двухфакторка при этом не обходится, её по-прежнему проходите вы сами,
просто через Telegram вместо визуального захода в эмулятор.

## Важно

- Пароль/сессия от Госключ нигде в коде не хранится — сессия живёт только
  внутри Android-контейнера после ручного логина. Файл `.env` содержит
  только токен Telegram-бота — держите его вне git (уже в `.gitignore`).
- Если контейнер redroid пересоздать (`docker compose down -v`), сессия
  сотрётся и понадобится повторный вход через scrcpy.
