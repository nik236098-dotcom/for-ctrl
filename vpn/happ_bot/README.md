# iPhone (Happ) — отдельный проект

Это отдельный VPN-продукт от WireGuard-версии (Android/Windows, `vpn/bot`) —
свой сервер (Xray, VLESS+Reality), свой бот, свои подписчики. Собран под
пользователей из России, которым нужно, чтобы российские сайты/банки
открывались напрямую (без VPN), а всё остальное — через сервер.

## Что где

- `vpn/server/install_xray.sh` — ставит Xray (VLESS+Reality) на сервере.
- `vpn/server/{add,remove,suspend,resume,show}_client_happ.sh` — управление
  одним клиентом (по имени).
- `vpn/server/xray_traffic.sh` — сырая статистика трафика по клиентам
  (используется ботом, см. ниже).
- `vpn/happ_bot/` — телеграм-бот подписки (профиль, устройства, оплата).

## Шаг 1. Сервер

```
sudo bash vpn/server/install_xray.sh
```

Выведет внешний адрес, публичный ключ и команду для выдачи первого ключа
(`add_client_happ.sh`) — но обычно клиентов заводит сам бот, вручную
скрипт нужен только для отладки.

## Шаг 2. Маршрутизация (ру-сайты напрямую)

Сама по себе ссылка `vless://` заводит только прокси — по умолчанию Happ
погонит через него весь трафик. Чтобы российские сайты и банки открывались
напрямую, один раз (это общий шаг, не для каждого пользователя) нужно
подключить в Happ готовый профиль маршрутизации — деплинк вида
`happ://routing/onadd/<...>`, собранный на основе проекта
[roscomvpn-routing](https://github.com/hydraponique/roscomvpn-routing)
(RU/BY-домены и приватные сети — напрямую, остальное — через прокси).

## Шаг 3. Бот подписки

```
sudo bash vpn/happ_bot/install_bot.sh
```

Требует уже поднятого Xray (шаг 1). Дальше:

```
sudo nano /opt/happ-vpn/happ_bot/.env
```

Обязательно заполнить `BOT_TOKEN` и `ADMIN_IDS`; для оплаты — токен(ы)
`CRYPTO_PAY_TOKEN` (@CryptoBot → Crypto Pay → Create App) и/или
`XROCKET_API_TOKEN` (@xRocket → Pay App → Create App). Можно включить оба
сразу — в боте появится выбор способа оплаты.

```
sudo systemctl enable --now happ-bot
sudo journalctl -u happ-bot -f
```

### Меню бота

- **👤 Профиль** — Telegram ID и срок подписки.
- **📱 Мои устройства** — список ключей (до `MAX_DEVICES` штук, по
  умолчанию 2), добавление/переименование/удаление, трафик по каждому.
- **💳 Оформить подписку** — тарифы из `PLANS` (дни:рубли в `.env`), оплата
  через CryptoBot или xRocket.
- **📚 Инструкция** — как поставить Happ и вставить ключ.

### Учёт трафика по устройствам

Нужен блок `"api"/"stats"/"policy"` в `config.json` Xray — `install_xray.sh`
добавляет его сам при новой установке. Если Xray был поднят ДО этой правки,
добавьте вручную и перезапустите `xray`:

```json
"api": { "tag": "api", "listen": "127.0.0.1:10085", "services": ["StatsService"] },
"stats": {},
"policy": { "levels": { "0": { "statsUserUplink": true, "statsUserDownlink": true } } }
```

(в `inbounds`/`outbounds` ничего менять не нужно — эти три ключа
самостоятельные, добавляются рядом).

### Оплата: два провайдера параллельно

- **CryptoBot** — настоящий фиатный счёт (`currency_type: fiat, fiat: RUB`),
  сумма именно в рублях, конвертирует сам CryptoBot.
- **xRocket Pay** — фиатных счетов не умеет, только крипто-активы. Бот сам
  переводит рублёвую цену тарифа в USDT по курсу `RUB_PER_USDT` из `.env`
  (курс статический, подправлять вручную по мере надобности — никакого
  внешнего запроса курса при выставлении счёта нет).

Оба варианта проверяются фоновой задачей раз в минуту (без вебхуков —
не нужен публичный HTTPS-адрес для бота).

## Ограничения (честно)

- Определить модель/тип устройства (iPhone vs Android, конкретная модель)
  по самому VLESS/Reality-подключению нельзя — протокол не несёт такой
  информации, а TLS-отпечаток намеренно унифицирован под Chrome (часть
  маскировки Reality). Название устройства — только то, что ввёл сам
  человек при переименовании.
- «Устройство подключено!» после выдачи ключа — оптимистичное сообщение,
  показанное сразу после генерации ключа, а не подтверждённый техническими
  средствами факт (Happ не даёт боту обратный сигнал об использовании
  ключа).
- Обычная (повседневная) DPI-фильтрация — не то же самое, что жёсткий
  режим «белых списков» во время тревог БПЛА: сервер, который проходит
  первую, не гарантированно проходит вторую (см. обсуждение в истории
  проекта) — это отдельная, ещё не до конца решённая задача.
