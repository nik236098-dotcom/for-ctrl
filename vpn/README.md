# RU VPN — свой VPN с российским IP для Android

Собственный VPN: сервер WireGuard на вашем VDS в России + Android-приложение,
которое собирается в APK и подключается к нему в одно нажатие. Внешний IP на
телефоне становится российским — работают Госуслуги, банки, RuStore, Госключ и
всё остальное, что не пускает зарубежные адреса.

## Главное, что нужно понимать сразу

**IP даёт не приложение, а сервер.** APK — это только клиент; «российским»
адрес становится потому, что трафик выходит в интернет с машины, физически
стоящей в России. Поэтому нужен VDS у российского хостера (Selectel, Timeweb,
Beget, RuVDS, VK Cloud, Яндекс.Облако — подойдёт самый дешёвый тариф,
200-400 ₽/мес, 1 vCPU / 1 ГБ RAM тянет несколько устройств). Готового
«российского IP» внутри самого приложения не бывает — иначе это был бы
чужой публичный VPN-сервис со всеми его рисками.

У вас уже есть VDS под `goskey-forwarder` — тот же сервер можно использовать
и под VPN, они друг другу не мешают (WireGuard занимает только UDP-порт).

Протокол — WireGuard: он в разы быстрее OpenVPN, держит переключение
Wi-Fi ↔ мобильный интернет без обрывов и почти не жрёт батарею.

## Что в папке

```
vpn/
├── server/                     на VDS в России
│   ├── install_wireguard.sh    установка и настройка сервера (один раз)
│   ├── add_client.sh           добавить устройство → готовый .conf + QR
│   └── remove_client.sh        отозвать доступ у устройства
└── android/                    исходники APK (Kotlin + библиотека WireGuard)
```

## Шаг 1. Сервер

На VDS (Ubuntu/Debian, root):

```bash
git clone <этот репозиторий> && cd for-ctrl
sudo bash vpn/server/install_wireguard.sh
```

Скрипт ставит WireGuard, включает форвардинг и NAT, поднимает интерфейс `wg0`
и запоминает параметры в `/etc/wireguard/ruvpn.params`. Порт по умолчанию —
UDP 51820, меняется переменной: `sudo WG_PORT=443 bash vpn/server/install_wireguard.sh`.

Если у хостера есть внешний firewall (security group) — разрешите в нём
входящий UDP на этот порт, иначе телефон не достучится.

## Шаг 2. Конфиг для телефона

```bash
sudo bash vpn/server/add_client.sh phone
```

Печатает готовый конфиг клиента, путь к файлу (`/etc/wireguard/clients/phone.conf`)
и QR-код прямо в терминале. Каждому устройству — свой конфиг
(`add_client.sh laptop`, `add_client.sh tablet`), отозвать доступ:
`sudo bash vpn/server/remove_client.sh phone`.

По умолчанию в туннель заворачивается **весь** трафик (`AllowedIPs = 0.0.0.0/0, ::/0`)
— только так внешний IP становится российским. IPv6 идёт в туннель тоже: это
защищает от утечки настоящего адреса, если мобильный оператор выдаёт IPv6.

DNS клиентам выдаётся Яндекс (`77.88.8.8`), чтобы имена резолвились
«по-российски». Поменять: `sudo WG_DNS="8.8.8.8" bash vpn/server/add_client.sh phone`.

## Шаг 3. APK

### Вариант А: собрать через GitHub Actions (без Android Studio)

1. В настройках репозитория добавьте секрет `WG_CONFIG` — целиком содержимое
   `phone.conf` из шага 2 (тогда конфиг вшивается в APK и приложение сразу
   готово к подключению; без секрета APK тоже соберётся, конфиг импортируется
   в приложении вручную).
2. Actions → «Сборка APK RU VPN» → Run workflow.
3. Скачайте артефакт `ruvpn-debug-apk`, перекиньте `.apk` на телефон,
   установите (нужно разрешить установку из неизвестных источников).

### Вариант Б: локально

Нужны JDK 17 и Android SDK (проще всего — Android Studio).

```bash
cd vpn/android
cp /путь/к/phone.conf app/src/main/assets/wg.conf   # необязательно
gradle assembleDebug           # обёртки ./gradlew в репозитории нет:
                               # её создаст Android Studio или `gradle wrapper`
# APK: app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`app/src/main/assets/wg.conf` в `.gitignore` — приватный ключ в репозиторий
не попадёт.

Debug-APK подписан отладочным ключом: для личного устройства этого достаточно.
Для «нормальной» подписи — `keytool -genkey -v -keystore ruvpn.jks ...`,
`assembleRelease` и `apksigner sign`.

## Как пользоваться приложением

Одна кнопка «Соединить» и одна «Вставить ключ» — больше знать ничего не нужно.

1. Взять ключ у бота: он присылает строку `ruvpn://…`, по нажатию она
   копируется.
2. В приложении — «Вставить ключ». Если ключ уже в буфере обмена, он
   подставится сам, останется нажать «Готово».
3. «Соединить». Первый раз Android спросит разрешение на VPN — системный
   диалог, появляется один раз.
4. «Откуда нас видно?» покажет адрес и страну: ✅ значит, что вы выходите
   в интернет через российский адрес.

Слов «конфиг», «WireGuard» и «импорт файла» в приложении нет намеренно:
человеку выдали ключ — он его вставил.

Чтобы VPN включался при загрузке телефона: Настройки Android → Сеть и
интернет → VPN → RU VPN → «Постоянный VPN».

## Сервис: бот, тарифы и оплата в @CryptoBot

`vpn/bot/` — телеграм-бот, который продаёт доступ и сам следит за сроками.
Без выданного им ключа подключиться нельзя.

Как это выглядит для человека:

1. `/start` — регистрация. Если включён `TRIAL_DAYS`, сразу даётся
   пробный период; если `INVITE_ONLY=1`, сначала спрашивается инвайт-код.
2. `/key` — бот заводит на сервере отдельного пира и присылает `.conf`
   файлом и QR-кодом. Приватный ключ генерируется на сервере.
3. Кнопка тарифа → счёт в @CryptoBot → оплата.
4. Срок кончился — ключи выключаются. Оплатил — включаются те же самые.

### Срок соблюдается по-настоящему

Это главное отличие от «выдал конфиг и забыл». Раз в
`ENFORCE_INTERVAL_SECONDS` (по умолчанию 60 с) бот сверяет сроки и
снимает пиров просроченных клиентов с интерфейса. Пересидеть можно
максимум минуту, а не сутки.

Ключ при этом **не удаляется, а приостанавливается**: блок пира
комментируется в `wg0.conf`, адрес остаётся закреплён за клиентом, файл
конфига цел. После оплаты `resume_client.sh` возвращает всё обратно, и
человек подключается тем же ключом — переустанавливать и переимпортировать
ничего не нужно. Удаляется ключ только по `/drop` (сам человек) или
`/kick` (админ).

### Оплата

Счета выставляются через Crypto Pay — это платёжный интерфейс самого
[@CryptoBot](https://t.me/CryptoBot): в нём открываете «Crypto Pay» →
«Create App» и получаете токен для `CRYPTO_PAY_TOKEN`. Клиент платит
внутри Telegram, никаких сайтов и эквайринга.

Вебхук не нужен: бот раз в минуту сам спрашивает статус выставленных
счетов, поэтому ни домена, ни белого IP, ни HTTPS не требуется.

Тарифы задаются строкой `PLANS=30:1,90:2.5,180:4.5` — «дней:сумма».
Валюта — `PRICE_ASSET` (USDT, TON, BTC…).

**Тестовый режим** включён по умолчанию: `CRYPTO_PAY_TESTNET=1`, счета
идут в @CryptoTestnetBot и деньги ненастоящие — можно прогнать весь путь
от кнопки до включения ключа, ничего не потратив. Для боевого режима
поставьте `0` и возьмите токен в обычном @CryptoBot.

### Команды

Клиент: `/start`, `/key [название]`, `/status`, `/drop N`, `/pay`.
Админ: `/invite [сколько]`, `/users`, `/extend <id> <дней>`,
`/kick <id>`, `/stats` (активные, работающие и приостановленные ключи,
трафик, сколько получено).

### Установка

```bash
sudo bash vpn/bot/install_bot.sh
sudo nano /opt/ruvpn/bot/.env      # BOT_TOKEN, ADMIN_IDS, CRYPTO_PAY_TOKEN
sudo systemctl enable --now ruvpn-bot
sudo journalctl -u ruvpn-bot -f
```

Установщик копирует `vpn/server` и `vpn/bot` в `/opt/ruvpn` под
владельцем root, заводит системного пользователя `ruvpnbot` без шелла и
через `sudoers` разрешает ему ровно шесть команд: выдать, показать,
приостановить, вернуть, удалить клиента и `wg show`. Больше бот на
сервере не может ничего — даже с утёкшим токеном.

### О чём помнить, запуская сервис

- Весь трафик клиентов выходит с вашего IP: `/stats` и `/users` — способ
  заметить, что кто-то качает торренты на общем канале.
- Один VDS за 300 ₽ тянет несколько десятков человек, пока они не начнут
  смотреть видео. Считайте по трафику, а не по числу подписчиков.
- Оферта хостера часто запрещает перепродажу VPN — проверьте свою до
  того, как продавать доступ, а не после.
- Конфиг с приватным ключом остаётся в переписке Telegram. Если это
  смущает — `CONFIG_MESSAGE_TTL_MINUTES=30`, бот удалит сообщение сам.

## Оформление

Экран сделан в стилистике кукольных мультфильмов конца 60-х: тёплая
бумага с зерном, выгоревшая палитра, чернильные обводки вместо теней,
крупная круглая кнопка с ободком.

Состояние связи показывают телефонная будка и ушастый герой рядом с ней.
Связи нет — окно будки тёмное, герой грустит. Связь есть — окно
загорается, герой улыбается и держит апельсин. Иконка приложения — его же
голова с ушами.

Иллюстрации нарисованы как vector drawable и генерируются из общего
шаблона (`hero_off` и `hero_on` отличаются ртом, лапами и апельсином),
поэтому масштабируются без потери качества и почти ничего не весят.

Тёмная тема — та же палитра в тёмном дереве; цвета иллюстраций в обеих
темах одинаковые.

Шрифты: **Kelly Slab** (заголовки) и **PT Sans** (текст), оба с кириллицей,
оба под SIL Open Font License — тексты лицензий лежат в `android/licenses/`.

## Что внутри приложения

Приложение использует официальную библиотеку `com.wireguard.android:tunnel` —
ту же реализацию протокола, что и приложение WireGuard из Play Market.
Своего криптокода здесь нет и быть не должно: собственная реализация VPN-протокола
почти гарантированно окажется дырявой.

| Файл | Назначение |
|---|---|
| `MainActivity.kt` | экран, разрешение на VpnService, вставка ключа, проверка IP |
| `VpnManager.kt` | обёртка над `GoBackend`: поднять/опустить туннель, состояние, статистика |
| `KeyStore.kt` | ключ `ruvpn://…`: разбор, хранение, запасной вариант — вшитый в APK |
| `IpChecker.kt` | запрос текущего внешнего IP и страны |

Минимальная версия Android — 7.0 (API 24).

## Если не подключается

| Симптом | Причина и что делать |
|---|---|
| Handshake не проходит, трафика нет | Порт закрыт: проверьте firewall хостера (security group) и `sudo ufw allow 51820/udp`. Проверить с телефона: сервер должен отвечать на `wg show` ростом `latest handshake` |
| Подключается, но сайты не открываются | Обычно MTU. Добавьте в `[Interface]` клиента `MTU = 1280` |
| Работает на Wi-Fi, не работает на мобильном | Оператор режет UDP. Перенесите сервер на `WG_PORT=443` (UDP 443 обычно проходит) |
| Всё поднялось, но IP не российский | Проверьте `AllowedIPs = 0.0.0.0/0, ::/0` в конфиге клиента — при частичном туннеле часть трафика идёт мимо |
| Соединение рвётся через минуту простоя | `PersistentKeepalive = 25` (скрипт ставит его по умолчанию) |

Отладка на сервере: `sudo wg show`, `sudo journalctl -u wg-quick@wg0 -f`.

## Ограничения и оговорки

- **Это личный VPN для доступа к российским сервисам** — трафик выходит с
  вашего сервера, вы за него и отвечаете. Скрипт не поднимает публичный
  VPN-сервис: это отдельная история с лицензиями и требованиями к операторам.
- **Скорость и стабильность = скорость вашего VDS.** Дешёвый тариф со 100 Мбит
  и общим каналом ведёт себя соответственно.
- **Обратное направление (из России наружу) может блокироваться DPI** — при
  использовании WireGuard *внутри* РФ для обхода блокировок соединение иногда
  режется. Для сценария «получить российский IP снаружи» это, как правило,
  не мешает; если всё же режет — существуют обфусцированные форки протокола
  (AmneziaWG), сервер под них ставится отдельно.
- **Альтернатива без своей сборки:** конфиг из шага 2 импортируется QR-кодом в
  официальное приложение WireGuard из Play Market — работает точно так же.
  Своё приложение имеет смысл, если хочется одну кнопку без лишних настроек,
  вшитый конфиг и проверку страны IP.
