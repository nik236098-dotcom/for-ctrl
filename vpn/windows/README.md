# Ru VPN для Windows

То же самое приложение, что и Android-версия: тот же космический дизайн,
та же кнопка-переключатель, тот же диалог ввода ключа. Собрано на
[Tauri](https://tauri.app/) (Rust + системный WebView2), фронтенд —
обычные HTML/CSS/JS, без сборщиков и npm.

## 0.2.1: несколько серверов

В окне «Сервер» (нажать на строку с IP) кроме основного ключа теперь есть
свои дополнительные серверы — например, запасной. «+ Добавить сервер»
принимает полный конфиг WireGuard (или ключ от бота) и кладёт его в список
рядом с основным ключом, не заменяя его. Выбранный сервер подсвечен;
переключение при включённом VPN сразу переподключает туннель, «✕» удаляет
сервер из списка (если через него были подключены — подключение переходит
на основной ключ). Россия/США у ключа от бота работают как раньше.
Подписку бота проверяют только у основного ключа: свои серверы от бота не
зависят. Список хранится в `servers.json` в папке данных приложения.

## 0.2.0: драйвер встроен, без отдельного WireGuard и без служб

До 0.2.0 приложение ставило официальный WireGuard for Windows и поднимало
туннель его службой `WireGuardTunnel$ruvpn`. Служба могла зависнуть в
состоянии «Запускается», и снять её без перезагрузки было нельзя.

Теперь туннель поднимает само приложение через WireGuardNT — драйвер
официального WireGuard, предназначенный для встраивания в свои программы:

* `wireguard.dll` (официальная подписанная сборка с
  download.wireguard.com) лежит прямо в установщике Ru VPN. CI скачивает
  последнюю версию при сборке и проверяет подпись WireGuard LLC; в git
  файл не хранится;
* при первом подключении драйвер ставится из этого файла сам, за несколько
  секунд, без окон;
* «Соединить» создаёт сетевой адаптер «Ru VPN», задаёт ключи, адреса,
  маршруты и DNS (`src-tauri/src/tunnel.rs`, `src-tauri/src/net.rs`);
  «Разъединить» удаляет адаптер, и всё уходит вместе с ним;
* служб Windows нет. Адаптер живёт, пока открыто приложение: закрыли окно
  или процесс упал — Windows сама удаляет адаптер, зависнуть нечему;
* отдельная программа WireGuard не нужна. Если она осталась от старых
  версий, она не мешает. Старую службу `WireGuardTunnel$ruvpn` приложение
  при запуске переводит в «отключена» и пробует удалить. Если она уже
  зависла в «Запускается», окончательно она исчезнет после ближайшей
  перезагрузки и больше не запустится;
* конфиг разбирается целиком ещё при сохранении ключа: Address, DNS, MTU,
  AllowedIPs и Endpoint проверяются тем же разбором, что и при
  подключении. Скрипты PreUp/PostUp не выполняются, как и в официальном
  клиенте по умолчанию.

Права администратора по-прежнему нужны: создавать сетевые адаптеры и
ставить драйвер Windows разрешает только им.

## Проверка конфигурации в 0.1.3

Перед сохранением ключа, после ответа сервера и перед запуском туннеля
проверяются секции, формат параметров и ключи WireGuard. Посторонний текст
(в том числе строка `s` из ошибки 1066/2), HTML/JSON вместо конфигурации и
обрезанные ключи отклоняются до перезаписи файла. Ошибка не содержит
переданный пользователем текст или значения ключей. Это предварительная
проверка структуры; сетевые параметры дополнительно проверяет WireGuard.

Для уже повреждённого сохранённого конфига открывается диалог замены ключа.
Нужно повторно скопировать полный ключ из бота; восстановить утраченные
данные из строки `s` невозможно. Сбой чтения буфера не блокирует диалог.

## Исправление службы Windows в 0.1.2

Состояние туннеля читается напрямую через Windows Service Control Manager,
без поиска английского `RUNNING` в выводе `sc.exe`. Ошибка проверки службы
показывается как неизвестное состояние и не запускает повторную установку.
Уже работающий туннель используется как есть; переходные состояния имеют
ограниченное время ожидания. При отключении клиент ждёт удаления службы,
прежде чем разрешить установку нового туннеля и удалить старый конфиг.
Команды установки/удаления туннеля завершаются по таймауту в 30 секунд.
Одновременные операции блокируются; второй экземпляр приложения поднимает
первое окно. После ошибок интерфейс возвращает управление пользователю.
В заголовке окна указана версия для проверки установленной сборки.

## Исправление обрывов в 0.1.1

Ошибки внешнего сервиса определения IP больше не отключают туннель.
Проверка выполняется раз в 30 секунд, отдельно от статуса службы.
Отключение возможно только после двух последовательных ответов
`{"status":"revoked"}` от собственного сервера ключей (HTTP 200).
Таймаут, DNS, HTTP 404/429/5xx и неожиданный ответ означают неизвестный
статус; соединение остаётся включённым. Результаты старых проверок после
переподключения, смены страны или сохранения ключа игнорируются.

Для проверки подписки сервер бота предоставляет новый read-only маршрут
`GET /key/{code}/status?country=ru`. Он читает срок подписки и состояние
устройства в базе, не выдаёт конфиг и не создаёт пиров. На старом сервере
маршрут отсутствует: Windows 0.1.1 всё равно устраняет ложные отключения,
но статус подписки будет неизвестен до обновления бота. Если весь трафик
уходит в уже неработающий туннель и сервер ключей недоступен, клиент также
не может подтвердить отзыв. Ограничение доступа остаётся на WireGuard-сервере.
Ключи, вставленные готовым конфигом без короткого кода, не проверяются
через этот маршрут.

Проверки:

```sh
node --test vpn/windows/tests/connection-health.test.cjs
python -m unittest discover -s vpn/bot/tests -p 'test_*.py'
# На Windows, из vpn/windows/src-tauri:
cargo test
```

## Что не проверено вживую

Собрано и проверено сборкой на `windows-latest` и разбором конфига в
тестах; настоящего подключения на живой Windows здесь нет. Если с
подключением что-то не так, приложение показывает текст ошибки драйвера
или Windows — пришлите его, поправим по факту.

## Сборка

Перед сборкой положите официальный `wireguard.dll` (amd64, из
`wireguard-nt-*.zip` с https://download.wireguard.com/wireguard-nt/) в
`src-tauri/resources/wireguard.dll` — без него Tauri не соберёт проект.

```
cd vpn/windows/src-tauri
cargo install tauri-cli --version "^2"
cargo tauri build
```

Готовый установщик (`.exe`, NSIS) — в
`src-tauri/target/release/bundle/nsis/`. В CI это делает
`.github/workflows/build-vpn-windows.yml` и публикует его в релиз
`ruvpn-windows-latest`.

Секрет `KEY_SERVER_URL` (тот же, что и для Android-сборки) встраивается на
этапе сборки — без него вставка короткого кода ключа не сработает.
