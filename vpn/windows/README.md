# Ru VPN для Windows

То же самое приложение, что и Android-версия: тот же космический дизайн,
та же кнопка-переключатель, тот же диалог ввода ключа. Собрано на
[Tauri](https://tauri.app/) (Rust + системный WebView2), фронтенд —
обычные HTML/CSS/JS, без сборщиков и npm.

## Почему внутри всё равно официальный WireGuard

Настоящий VPN-туннель на Windows требует ядерного драйвера сетевого
адаптера — у WireGuard это подписанный компонент Wintun. Свой драйвер с
нуля не собрать и не подписать реалистичными силами, поэтому это
приложение не заменяет официальный WireGuard for Windows, а управляет им
из-под капота:

* при первом подключении, если `wireguard.exe` не найден, приложение
  сначала пробует по-настоящему тихий путь: находит прямую ссылку на
  MSI-пакет последней версии и ставит его через `msiexec /quiet` — это не
  предположение, а стандартное поведение Windows Installer, без единого
  окна. Если это почему-то не получилось (страница со ссылками изменила
  формат и т.п.) — откатывается на официальный установщик (.exe), у
  которого, по отзыву с реального устройства, окно само не закрывается и
  нужно нажать «Установить» руками; на этот случай приложение
  предупреждает тостом заранее;
* после этого разового шага пользователь больше не открывает и не видит
  окно самого WireGuard — только это приложение: вставил ключ, нажал
  кнопку;
* «Соединить»/«Разъединить» под капотом — это `wireguard.exe
  /installtunnelservice <conf>` и `/uninstalltunnelservice ruvpn`
  (управление системным сервисом тунеля).

Управление сервисом тунеля требует прав администратора — поэтому всё
приложение целиком запрашивает их один раз при запуске (см.
`src-tauri/windows/app.manifest`), как и делает сам официальный клиент.

## Что не проверено вживую

Собиралось и проверялось только через CI-сборку на `windows-latest` —
здесь нет доступа к настоящей Windows-машине, чтобы руками запустить
готовое приложение и посмотреть на реальное подключение. Особо:

* реальные цифры трафика (Получено/Отправлено) читаются через
  предполагаемый именованный канал `\\.\pipe\WireGuard\ruvpn` тем же
  UAPI-протоколом, что `wg show` на Linux — если у WireGuard for Windows
  канал называется иначе, приложение просто покажет 0 КБ, на само
  подключение это не влияет (см. комментарий у `read_transfer_stats_blocking`
  в `src-tauri/src/main.rs`);
* тихая установка через MSI (`find_latest_msi_url`/`install_via_msi`) —
  сам `msiexec /quiet` гарантированно без окна, но поиск ссылки на
  актуальный MSI на странице загрузок разбором HTML не проверен вживую;
  если формат страницы окажется другим, разбор просто не найдёт файл, и
  приложение откатится на видимый .exe-установщик — ничего не сломается,
  просто это конкретное окно снова станет видимым;
* сразу после установки WireGuard есть небольшая пауза (2-3 сек.) перед
  первой попыткой поднять тунель и один повтор при неудаче — предположение
  о причине жалобы «после установки ничего не работает», не подтверждённая
  причина (проверить состояние сразу после install на реальной Windows
  здесь нечем).

Если что-то из этого не сработает на реальном устройстве — дайте знать,
поправим по факту (как и с Android-версией).

## Сборка

```
cd vpn/windows/src-tauri
cargo install tauri-cli --version "^2"
cargo tauri build
```

Готовый установщик (`.exe`, NSIS) — в
`src-tauri/target/release/bundle/nsis/`. В CI это делает
`.github/workflows/build-vpn-windows.yml` и публикует его в релиз
`ruvpn-windows-latest`.

Секрет `KEY_SERVER_URL` (тот же, что и для Android-сборки) встраивается на
этапе сборки — без него вставка короткого кода ключа не сработает.
